How the score works

The score adds up six checks, out of 100 points. It uses only what the catalogue publishes about each dataset, so it tells you how well a dataset is maintained and documented, not whether its values are correct. Open the dataset and look at the files before you depend on it.

CheckPointsHow points are given
Freshness25Compares the newest data file date with the promised frequency. On schedule (within 1.5× the interval plus a week): 25. Late (within 3×): 12. Overdue: 0. With no fixed schedule: changed in the last year 18, in 1–3 years 10, older 4. Archives 15. No dates 10.
Open format1515 for an open machine-readable format (CSV, JSON, GeoJSON, XML, GeoPackage, Shapefile, KML…). 9 for Excel, file geodatabases, ZIP or map services only. 0 if the data is only PDF, web pages or images.
API access1010 when at least one file is loaded in the portal's DataStore and can be queried row by row. 7 for a web map or feature service. 0 otherwise.
Documentation25Description length (up to 7), column descriptions as a document or in the metadata (8), methodology notes (5), time coverage stated (3), contact email (2).
Portal checks15Share of the portal's own file checks the publisher marked as met: UTF-8, comma separator, not compressed, standard projection, empty unknown values, ISO dates, '.' decimals, simple booleans. 8 when none were filled in.
Licence1010 when commercial reuse is allowed (CC BY, CC BY-SA, CC0, OGL). 6 for no-derivatives licences. 3 for non-commercial licences.

Grades: A from 85, B from 70, C from 55, D below 55. Column lists come from the main queryable table of each dataset (the most recently changed data file in the DataStore). Views are the portal's own counters; "lately" means the last 14 days.
